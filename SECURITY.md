# Security Policy

## Supported Versions

This project follows [Semantic Versioning](https://semver.org/) and currently
uses the `1.x` release line (current version: `1.1.7`). The table below shows
which versions receive security updates.

| Version  | Supported                        |
| -------- | -------------------------------- |
| 1.1.x    | :white_check_mark: Active        |
| 1.0.x    | :white_check_mark: Security fixes only |
| < 1.0.0  | :x: Not supported                |

## Reporting a Vulnerability

If you believe you have found a security vulnerability in this project,
please report it using one of the following private channels:

- **GitHub Security Advisories**: Open a private security advisory through
  [GitHub's Security tab](../../security/advisories/new) instead of a public issue.
- **Email**: Contact the maintainers directly via the email listed in the
  repository's profile or package.json.

### What to Include

When reporting a vulnerability, please include:

- A detailed description of the issue
- Steps to reproduce the vulnerability
- Any relevant logs or proof-of-concept code
- The potential impact of the vulnerability

### Response Timeline

- We aim to acknowledge new vulnerability reports within **5 business days**
- We will provide regular status updates (at least every **2 weeks**) until
  the issue is resolved
- When a fix is available, we will publish a new release and update this
  SECURITY.md file with any relevant information

### Disclosure Policy

- Please do not publicly disclose the vulnerability until we have had a
  reasonable opportunity to address it
- We will credit security researchers who responsibly disclose vulnerabilities
  (unless they prefer to remain anonymous)

Thank you for helping keep this project and its users safe!
